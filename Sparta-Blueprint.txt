S.P.A.R.T.A — ARCHITECTURAL BLUEPRINT
========================================
Super Personal Assistant for Real-time Tactical & Autonomous

1. SYSTEM OVERVIEW
------------------
S.P.A.R.T.A is a hierarchical multi-agent system built on top of the
opencode engine. It extends opencode's agent capabilities with a
tactical command structure, domain-expert skills database, and
safety-governed deployment framework.

3. ARCHITECTURAL LAYERS
------------------------
  Layer 1: Identity & Governance (SPARTA.md, SPARTA-SKILLS.md)
    - Core values, operating principles, security protocols
    - Faculty-driven risk model (41 faculties, 5 risk levels)
    - Auto-update system for new domains

  Layer 2: Agent System (sparta.txt, sparta.ts)
    - Master agent with hierarchical delegation
    - 4-tier model (Master, Senior, Junior, Worker)
    - Cross-validation for security-sensitive operations
    - Persistence advisory for scheduled tasks

  Layer 3: Model Tiering (model_tiers.json)
    - 3 model tiers with complexity-based routing
    - Cross-validation rules for security operations
    - Token limits per tier (8K/32K/unlimited)

  Layer 4: Compression (packages/opencode/src/compression/)
    - Multi-stage context optimization pipeline
    - Filters for git, docker, build, test, shell, stacktrace
    - Prose compression, deduplication, smart truncation
    - Validation gate for quality control

  Layer 5: Isolation (packages/opencode/src/sandbox/)
    - Sandbox manager for secure execution
    - Ring buffer for resource tracking
    - Egress control for network access
    - Vault for credential management

  Layer 6: Specialized Tools (packages/opencode/src/tool/)
    - hierarchy-delegate: Multi-agent task decomposition
    - stealth-browser: Anti-detection browser automation
    - sandbox: Sandbox lifecycle management
    - signin: OAuth/credential flow

  Layer 7: Presentation (packages/tui, packages/ui)
    - Terminal UI theme (sparta.json)
    - Desktop UI theme (sparta.json)

4. DATA FLOW
-------------
  User Input
    -> Master Agent (highest-intelligence model)
      -> Complexity Assessment
        -> Simple: Direct tool calls (Worker mode)
        -> Medium: Decompose -> Junior helpers for mechanical work
        -> Complex: Decompose -> Senior/Junior hierarchy
          -> Parallel delegation via hierarchy-delegate
            -> Cross-validation for security ops
              -> Synthesis into coherent response
    -> User Output

5. SECURITY MODEL
------------------
  Risk Level Classification:
    Critical:  Medical, Legal, Emergency Response (disclaimers required)
    High:      Finance, Transportation, Real Estate (user confirmation)
    Moderate:  Engineering, Sciences, Trades (standard guardrails)
    Low:       Arts, Business Ops, Media (minimal restrictions)

  Universal Safeguards:
    - Dynamic guardrails calibrated to capability limits
    - Sensitive content protocol with warning banners
    - Session-scoped permissions (never cross-session)
    - Destructive action guard (user confirmation required)
    - Runaway reasoning cap (7 levels)
    - Skill cascade breaker (failures don't auto-trigger adjacent skills)
    - Audit trail for all skill activations

6. DEPLOYMENT MODEL
--------------------
  This public repo contains the Sparta-specific additions only.
  The full opencode engine (required runtime) is installed separately
  as an npm dependency.

  Required runtime dependency: opencode ^1.18.0

  Future Workflow:
    - Private repo: Full monorepo development (engine + Sparta)
    - Public repo: Cherry-picked Sparta-specific commits
    - CI/CD: Automated extraction of Sparta changes for public release

7. EXTENSIBILITY
-----------------
  Auto-Update System (SPARTA-SKILLS.md Section):
    When a new domain is encountered:
    1. Detect gap in existing faculties
    2. Search 5+ authoritative sources
    3. Generate 8-12 domain-specific skills
    4. Append to SPARTA-SKILLS.md
    5. Update security mapping

  New tools can be added to packages/opencode/src/tool/ and registered
  through the tool registry.

8. COMPRESSION PIPELINE ARCHITECTURE
--------------------------------------
  Input -> Command Detector -> Deduplicator
    -> Preservation (important content markers)
      -> Prose Engine + Prose Rules
        -> Generic Filter
          -> Domain-specific filters (Docker, Git, Build, Test, Shell, Stacktrace)
            -> Smart Truncation
              -> Validation Gate
                -> Output
